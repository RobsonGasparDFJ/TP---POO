## 2. Fundamentação Teórica e Arquitetural

### 2.1. O que é Maven e por que a estrutura do projeto é assim?

O **Apache Maven** é uma ferramenta de automação de compilação e gerenciamento de dependências. Ele exige uma convenção sobre configuração chamada **Standard Directory Layout**:

* **`src/main/java/`**: Pasta raiz do código-fonte Java. As subpastas (ex: `app/`) definem os pacotes (`package app;`). Se o código não estiver nessa estrutura, o compilador e as IDEs não reconhecem as raízes de código e o mapeamento de pacotes falha.
* **`src/main/resources/`**: Pasta raiz para arquivos estáticos, assets e configurações que **não são código Java**. O Maven copia o conteúdo desta pasta diretamente para a raiz do *classpath* final da aplicação.

### 2.2. Estrutura e Função do `pom.xml`

O `pom.xml` (Project Object Model) é o manifesto do projeto. As tags obrigatórias são:

* **`groupId`**: Identificador da organização ou pacote base do projeto.
* **`artifactId`**: Nome do projeto/biblioteca compilada.
* **`version`**: Versão do projeto.
* **`<dependencies>`**: Lista de bibliotecas remotas que o Maven deve baixar automaticamente do repositório central (Hibernate, Dialeto SQLite e Driver JDBC) e incluir no *classpath*.

### 2.3. O que é JPA e Hibernate?

* **JPA (Jakarta Persistence API):** É uma **especificação** (um conjunto de interfaces e regras) que dita como o Java deve fazer Mapeamento Objeto-Relacional (ORM). O JPA não executa código diretamente, apenas define os padrões.
* **Hibernate:** É o **provedor/framework (implementação concreta)** que executa o JPA. Ele lê os dados em memória, traduz anotações Java para comandos SQL e executa esses comandos no banco de dados.

### 2.4. Estrutura do `persistence.xml`

A especificação JPA exige que o arquivo de configuração se chame exatamente `persistence.xml` e esteja no diretório `META-INF/` dentro da pasta de recursos (`src/main/resources/META-INF/persistence.xml`).

* **`<persistence-unit>`**: Define o nome do contexto de persistência usado na chamada `Persistence.createEntityManagerFactory("meu-sqlite-pu")`.
* **`jakarta.persistence.jdbc.url` / `driver**`: Parâmetros para instruir a biblioteca a abrir ou criar o arquivo `.db` local via SQLite JDBC.
* **`hibernate.dialect`**: Informa ao Hibernate qual variação de linguagem SQL ele deve gerar (neste caso, o dialeto do SQLite).
* **`hibernate.hbm2ddl.auto` (`update`)**: Instrução que faz o Hibernate inspecionar as classes anotadas com `@Entity` e executar automaticamente comandos `CREATE TABLE` / `ALTER TABLE` no arquivo SQLite.

## 3. Funcionamento do Mapeamento, Getters, Setters e Consultas

* **Consultas (`em.find`) e Getters:**
O método `em.find(Conta.class, id)` executa uma consulta SQL (`SELECT`) no banco de dados SQLite, lê o registro retornado, instancia o objeto `Conta` na memória da JVM e preenche seus campos. Os métodos **Getters** apenas retornam o valor que já foi carregado para a memória. Eles não possuem anotações nem executam consultas SQL internas.
* **Atualizações (Setters) e Confirmação de Transação (`commit` / Dirty Checking):**
Invocar um método **Setter** (ou um método de negócio como `depositar()`) altera apenas o valor da variável na memória RAM durante a execução. O Hibernate monitora o estado dos objetos carregados. Quando o método `em.getTransaction().commit()` é executado, o Hibernate compara o estado atual do objeto com o estado original carregado do banco (mecanismo conhecido como *Dirty Checking*). Se houver divergência, ele gera e executa o comando SQL `UPDATE` no arquivo SQLite automaticamente.
